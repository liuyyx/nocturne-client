## 0. 本轮已修复（真机验证）

### 0.1 1.8.9 界面完全不可见（阻断）— 已修

**根因**：`GL_CULL_FACE` 的真实状态是**开启**，而 1.8.9 的 `GlStateManager`（`bfl`）缓存认为它已关。
`GlApi.enable/disable` 原先「桥命中就 return」，于是 `beginFrame()` 的 `disable(GL_CULL_FACE)` 变成**空操作**；
而固定管线后端的正交投影翻转了 y 轴（`glOrtho(0, w, h, 0, -1, 1)`），四边形在屏幕空间成为**顺时针**，
在默认 `GL_CCW` 正面规则下是背面 → 整个界面被背面剔除。

**为什么难查**：`glClear` 不受剔除影响（所以「清屏可见」是假阴性）；驱动不报任何 GL 错误；
立即模式与顶点数组两条路径同时失效，看起来像「几何没到光栅器」。

**证据链**（探针实测，`-Dnocturne.ui.debug=probe`）：
1. `glClear` 绿屏可见 → 钩子点/线程/帧缓冲/呈现次序全部正确；
2. `glReadPixels` 回读中心像素仍为绿 → 几何确实未被光栅化；
3. 绘制瞬间状态读数：`proj=[0.002,-0.004,-1,1]`（就是我们给 854×480 的 ortho）、`mv=identity`、
   `scissor/light/alphatest/stencil=false`、`mask=[1,1,1,1]`、`cull=true` ← **异常项**；
4. 改为「桥 + 真实调用」后，同一探针左半屏变为 `[0,0,255,255]`（蓝）。

**修复**（`ui/.../gl/GlApi.java`）：
- `setCap(cap, enabled)`：先经状态桥同步其缓存、**再无条件下发真实 GL 调用**，两者从此必然一致；
- `blendFunc` 同样处理；
- 顺带修掉 `StateManager` 用**零参**名字解析 `blendFunc`、误绑到 `bfl.b()`（= `func_179099_b` = `popAttrib`）
  的缺陷（真机日志实测 `REFLECT FAIL bfl.b(Integer,Integer) -> wrong number of arguments`）——
  现按 `(int,int)` 精确匹配；
- `GlRenderer.beginFrame()` 复位 `GL_SCISSOR_TEST`（防止上一帧裁剪泄漏把整帧裁成 0 像素）；
- 调试模式外零额外开销（能力位回读只在 `-Dnocturne.ui.debug` 下进行）。

### 0.2 静默失败可见性（高）— 已修

`Reflect.call` 原先吞掉全部 `Throwable` 且不留痕，导致「GL 调用失败」与「功能没触发」完全同形。
现于 `-Dnocturne.ui.debug` 下按「声明类.方法名」去重打印 `[nocturne] REFLECT FAIL ...`。
本次定位 cull/blendFunc 两个缺陷全靠它。

## 7. 文档与事实不一致（摘要）

- `docs/VERSION-MATRIX.md` §1 称表规模 61 类（实为 71/73）；Fatality 移植矩阵对 1.8.9/1.12.2 标「待真机」与「1.12.2 通过」自相矛盾；§4 对 26.2 帧钩子目标的描述与 `NocturneAgent` 实现相反。

- `docs/research/draw-api-per-version.md:612` 称「换缓冲钩子太晚（`Display.update` 在本帧提交之后）」——按 LWJGL2 源码 `update(){update(true)}` 内**先 `swapBuffers()` 后 `processMessages()`**，钩子插在首指令前即「先绘制后交换」，该表述不成立。
- `THIRD-PARTY-NOTICES.md` 漏列 in-repo 的 `vendor/vape`（CC0）与 `vendor/setsuna-gui`。
